# 七天 Agent 项目练习路线

每天约 30–60 分钟。记录自己做过什么、出现过什么问题、如何验证。

| 天数 | 练习 | 验收 |
| --- | --- | --- |
| 1 | 运行 demo，理解三个工具 | 能解释每轮输入、工具结果和停止条件 |
| 2 | 添加两份个人学习笔记 | 相同问题能检索到新文件；报告有来源 |
| 3 | 配置 Key，运行真实模式 | 保存一次模型自主工具选择的记录，检查费用与来源 |
| 4 | 修改 Agent 指令，比较两种回答格式 | 用相同三个问题手工记录优缺点 |
| 5 | 新增一个只读工具，例如按标题列出章节 | 添加正确调用、错误参数和边界情况测试 |
| 6 | 扩展评估到 15 个问题 | 包括中英文、无资料、同义词和模糊问题；记录失败例 |
| 7 | 整理 README 与演示记录 | 能独立运行、解释架构、展示自己实现的改动 |

## 面试讲解顺序

1. 解决的问题：普通聊天无法直接读取你的笔记；需要由应用提供工具。
2. 核心流程：模型提出函数调用，代码校验并执行，结果回传，重复直到答案。
3. 关键取舍：零第三方依赖便于入门；关键词检索简单可测，但语义召回有限。
4. 验证证据：自动化测试、固定离线评估、自己运行真实模型的人工核对。
5. 下一步：笔记切块、向量检索、聊天状态、UI、更严格的答案评估。

## 项目经历写法

完成理解和亲自改造后，可按实际内容写：

> 开发本地学习资料 Agent，使用 Node.js 和 OpenAI Responses API 实现工具调用循环；提供笔记检索、来源标注和报告导出，并加入调用预算、路径限制与自动化测试。

不要声称自己做了尚未完成的改造，也不要把个人练习写成某公司的实习。离线评估的通过率不是大模型回答准确率。

## 最值得亲自尝试的第一个改动

为 `read_note` 添加 `start_line` 和 `end_line` 参数。同步修改工具 schema、运行时参数校验、行号引用检查和测试。验收：能够读取第 161 行以后的内容，同时禁止负数、越界和超大区间。
